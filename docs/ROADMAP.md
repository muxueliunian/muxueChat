## 自定义 OpenAI 兼容供应商（2026-08-05 确认的方向调整）

原先「仅限第二种 Provider = 局域网 CLIProxyAPI」的限制已由用户确认解除，改为：

- 第二类 Provider 是**协议**而非具体服务：任何 OpenAI 兼容的 `http(s)://` 端点。
- 用户可自定义供应商名称、Base URL、API Key，保存多个并随时切换；原 CLIProxyAPI 配置降级为其中一条普通记录。
- 每个供应商的 API Key 占独立 Keystore alias，删除供应商时一并清除。
- 模型不再手填单值：通过 `GET {base}/models` 拉取并缓存，失败时回退手填；模型选择入口从设置页移到聊天页顶栏。
- 每个供应商可填 `reasoning_effort` 思考等级（预设 low/medium/high，可自填其他值，留空则不发送），并解析 `reasoning_content` / `reasoning` 展示思考过程。
- 明文 HTTP 经用户确认开放（用于局域网自建服务），风险由用户承担；UI 会在 http 端点上给出提示。
- 除已批准的 xAI 订阅 OAuth/Responses 适配器外，不增加其它 OAuth 或厂商私有协议适配，也不引入通用多 Provider SDK。

详细设计与任务拆分见 `docs/CUSTOM_PROVIDER_PLAN.md`。

## realme Neo7 UI 优化规划（2026-10-02，待实施）

目标是让日常聊天与长篇 RP 的阅读、状态修正和设定选择更顺畅。本节是本轮规划，不代表所列改动已经实施。当前结构依据源码核对；设备只完成安装/启动检查，没有把未执行的页面操作写成真机发现。

### 设备与设计基线

- 实测设备：realme Neo7 / RMX5060，Android 16 / API 36，1264×2780，当前密度 560 dpi，系统字体倍率 1.0。未扣系统栏的逻辑尺寸约 361×794 dp；实际可用高度还受系统栏、键盘影响。
- 仅以这台手机验收，不增加其它机型、平板、横屏或分辨率矩阵；继续检查同机的现有 App 显示档位、键盘与系统栏。
- 保持现有暖色阅读风格和系统无衬线字体，不引入新字体/图标/渲染依赖。正文起点沿用 16sp / 26sp 行高，辅助说明 12sp / 18sp；调整依据同机阅读结果。
- 沿用 `Color.kt`：纸色背景 `#F7F5EF`、表面 `#FBFAF5`、正文 `#2B2A26`、次级文字 `#6B6761`、橄榄强调 `#626345`、分隔线 `#E2DDD0`。深色模式沿用已有色板，保留文字/图标状态提示。
- 尺寸使用 `Dimens.kt` 的 4/8/12/16/24dp 间距与现有圆角，触控目标 48dp。内容左对齐，层次由标题、留白和分隔表达，减少重复卡片与说明。

## RP 模式初步方向

RP 模式已经进入第一版可用状态，后续深化仍不要做成不可维护的硬编码 prompt。

已确认方向：

- RP 模式是会话级显式开关。
- 一个会话当前绑定一个角色卡与一个世界观。
- 角色卡已经是 domain model，不只是一个 system prompt 文本框。
- 角色卡至少应考虑：
  - 角色名称
  - 简介
  - 人设描述
  - 说话风格
  - 世界观/场景
  - 用户身份
  - 开场白
  - 禁止事项
  - 记忆/关系进展
- 角色卡本地保存，使用 Room。
- Prompt 拼接由 `PromptComposer` 负责，不要在 UI 或 API Client 中拼字符串。
- RP 模式应能和普通聊天模式共存。
- RP 设置使用会话级 `ConversationRpSettings`，不要污染任一 Provider DTO。
- 主角档案属于会话级 RP 设置，不写进角色卡。
- 角色卡内容可能非常私密，不允许写入日志。

## 状态栏定义 v1

状态栏定义跟随角色卡保存，当前数值跟随会话保存。

每个状态条字段：

- 名称。
- 最小值。
- 最大值。
- 初始值。
- 状态含义。
- 变化规则。

Prompt Composer 规则：

- 模型只能输出角色卡定义过的状态条。
- 模型不能新增、改名或遗漏状态条。
- 数值必须保持在定义范围内。
- App 保存状态面板前会再次按角色卡定义过滤并夹紧数值。
