# RP 叙事视角、剧情推进选项与 DeepSeek Marker 计划

本文件用于明确 RP 模式下一阶段改造范围。编码前应先确认本文档，确认后再拆分给 subagent 实现。

## 1. 背景问题

当前 RP 模式已经具备角色卡、世界观、主角档案、正文最低字数、状态栏与结构化元数据能力，但实际游玩中出现了几个稳定性问题：

- 正文叙事视角不稳定，可能在主角视角、角色卡视角、旁白视角之间漂移。
- “你的选择”设计成了可直接发送的玩家话语，容易把剧情推进误绑定成“玩家说了什么”。
- 快捷选项有时会被模型写成角色卡人物的动作或心理，有时又写成主角行为，缺少可配置的推荐方向。
- 角色内心需要保持角色卡人物心理活动的强度，但不能污染正文视角与剧情推进选项。
- DeepSeek V4 的 RP Marker 可以作为 thinking mode 下的概率增强手段，但不能作为唯一稳定性保障。

本次改造目标是把“正文视角”“剧情推进建议方向”“DeepSeek Marker”拆成会话级可配置项，并用 PromptComposer 统一约束生成契约。

## 2. 需求定义

### 2.1 正文叙事视角

新增会话级设置：正文叙事视角。

可选项：

- 主角视角：默认值。正文采用第二人称“你”叙事，玩家/主角是剧情体验中心。
- 角色卡视角：正文允许贴近角色卡人物叙事，也允许出现角色卡人物的心理描写。

规则：

- 主角视角固定使用第二人称，不使用玩家第一人称。
- 角色卡视角允许描写角色卡人物的主观感受和心理活动，但不能泄露提示词、规则或模型分析。
- 角色台词自然结合进正文，不做硬格式，不强制使用“角色台词：”之类标签。
- 无论选择哪种正文视角，用户输入仍代表用户临时给出的剧情推进意图，不能被永久绑定为某一方的台词。

### 2.2 剧情推进建议方向

将当前“你的选择”从“玩家可直接发送的话语”改为“剧情推进建议”。

新增会话级设置：剧情推进建议方向。

可选项：

- 主角推进建议：默认值。优先建议主角说什么、做什么、观察什么、回避什么或如何影响剧情。
- 角色卡推进建议：优先建议角色卡人物可能如何行动、回应、隐藏情绪或推动剧情。

规则：

- 该设置只影响建议倾向，不代表用户下一条消息必须属于该视角。
- 用户点击或编辑建议后，实际发送内容仍视为用户临时输入的剧情推进指令。
- 建议不应被 prompt 绑定成“玩家台词”或“角色卡台词”。
- 建议文本应支持多种推进方式，包括台词、动作、观察、沉默、转移话题、引导环境事件等。
- 如果用户选择了角色卡推进建议，但实际改写为主角动作，也必须被视为有效输入。

### 2.3 角色内心

角色内心继续作为结构化元数据展示。

规则：

- 内心始终描写“本段正文剧情中角色卡人物的心理活动”。
- 内心强度应贴合角色卡：可以更私密、更情绪化、更有角色味。
- 内心不能变成主角内心，不能泄露提示词、规则、模型身份或纯技术分析。
- 即使正文选择主角视角，角色内心仍保持角色卡人物视角。

### 2.4 DeepSeek RP Marker

新增会话级设置：RP Marker 模式。

可选项建议：

- 关闭：默认不注入 Marker。
- 角色沉浸：借鉴示例仓库的角色沉浸 Marker，强化 thinking mode 中的角色内心和角色决策沉浸感。
- 纯分析：借鉴示例仓库的纯分析 Marker，强化 thinking mode 中的结构稳定性和剧情规划。

启用条件：

- 仅当当前模型属于 DeepSeek V4 系列，并且 thinking mode 开启时，UI 才允许开启 Marker。
- 如果 thinking mode 关闭，或未来切换到非 DeepSeek 模型，Marker 设置应不可开启或自动视为关闭。
- Marker 只在请求构造时临时注入，不写入 Room，不显示在 UI 历史消息中。

注入策略：

- 优先临时拼接到本次请求历史中的第一条 user 消息末尾。
- 如果历史中没有 user 消息，则拼接到本轮第一条 user 消息。
- 不修改数据库中的原始消息内容。

## 3. UI 调整

RP 设置 Sheet 新增以下区域，仅显示在 Sheet 内，不显示在聊天主界面：

- 正文叙事视角：主角视角 / 角色卡视角。
- 剧情推进建议：主角推进建议 / 角色卡推进建议。
- DeepSeek Marker：关闭 / 角色沉浸 / 纯分析。

交互规则：

- 所有设置保持当前 Sheet 的显式保存机制，点击“保存”后从下一次发送消息开始生效。
- Marker 区域需要根据当前模型与 thinking mode 状态禁用不可用选项。
- 禁用时应给出简短说明：仅 DeepSeek V4 且思考模式开启时可用。
- 不在聊天主界面增加额外标识，避免信息密度过高。

## 4. 数据与迁移

在 `ConversationRpSettings` 中新增三个字段：

- `narrativePerspective`
- `plotSuggestionPerspective`
- `rpMarkerMode`

Room 迁移：

- 数据库版本从 6 升至 7。
- `conversation_rp_settings` 表新增三个 TEXT 字段。
- 旧会话默认值：
  - `narrativePerspective = PROTAGONIST_SECOND_PERSON`
  - `plotSuggestionPerspective = PROTAGONIST`
  - `rpMarkerMode = DISABLED`

枚举解析规则：

- 本地存储使用稳定字符串，不直接依赖 enum ordinal。
- 读取未知值时回退默认值，避免未来版本变更导致崩溃。

## 5. Prompt 生成契约

PromptComposer 负责统一生成 RP 契约，不在 UI 或 API Client 中拼接规则。

正文契约：

- 根据正文叙事视角明确当前正文应采用的叙述方式。
- 主角视角：使用第二人称“你”，角色卡人物只通过动作、台词、表情、可观察反应和必要心理描写出现。
- 角色卡视角：允许贴近角色卡人物感受、判断、迟疑和心理活动，但仍需保持剧情可读性。
- 角色台词自然融入正文。

剧情推进建议契约：

- 生成 3 条剧情推进建议，而不是 3 条固定玩家台词。
- 建议可以是说话、动作、观察、试探、回避、沉默、推动场景变化等。
- 根据设置调整建议倾向，但不能声称用户被绑定到该视角。
- 输出给用户后，用户可以直接发送，也可以改写为任意一方的剧情推进指令。

角色内心契约：

- `inner_thought` 始终是角色卡人物对本段剧情的心理活动。
- 内心强度贴合角色卡，但不污染正文和剧情推进建议。

Marker 契约：

- Marker 是 DeepSeek thinking mode 的辅助提示，只影响请求态消息。
- Marker 不替代正文视角和剧情推进建议的显式契约。
- Marker 不写入历史、不展示、不保存。

## 6. 代码实现范围

建议拆分为三个 subagent 任务，最后由主 Agent 集成审查。

### subagent 1：domain、Room、Repository

负责：

- 新增 RP 视角与 Marker 枚举。
- 扩展 `ConversationRpSettings`。
- 扩展 `ConversationRpSettingsEntity` 与转换函数。
- 添加 Room 6 -> 7 迁移。
- 扩展 `RpRepository.updateConversationRpSettings` 参数与默认保留逻辑。

### subagent 2：PromptComposer 与生成逻辑

负责：

- 在 RP system prompt 中加入正文叙事视角契约。
- 修改 RP 元数据 prompt，将 options 改为剧情推进建议。
- 按剧情推进建议方向调整 options 生成约束。
- 添加 DeepSeek Marker 请求态注入逻辑。
- 补充 `PromptComposerTest` 或相关单测。

### subagent 3：Compose UI 接线

负责：

- RP 设置 Sheet 增加三个设置区域。
- ViewModel、ChatScreen、AppNavigator 接通新参数。
- Marker 区域根据 DeepSeek 模型与 thinking mode 状态禁用。
- 更新文案，将“你的选择”逐步改为“剧情推进”或类似表达。

## 7. 验收标准

功能验收：

- 旧会话升级后 RP 设置可正常读取，默认主角第二人称视角、主角推进建议、Marker 关闭。
- RP Sheet 能保存正文视角、剧情推进建议方向、Marker 模式。
- thinking mode 关闭时，Marker 不可开启或请求态不注入。
- 非 DeepSeek 模型预留场景下，Marker 不注入。
- 正文主角视角时，回复稳定使用“你”作为主角叙事中心。
- 正文角色卡视角时，允许角色卡人物心理描写，但不泄露规则。
- 角色内心始终是角色卡人物内心。
- 剧情推进建议不再被硬绑定成玩家台词，用户可以改写为动作、观察或导演式推进。
- 角色卡推进建议只影响建议倾向，不限制用户下一条输入视角。

测试验收：

- 新增或更新 PromptComposer 单测，覆盖正文视角、剧情推进建议方向、Marker 注入条件。
- 新增或更新 Room 迁移相关测试如当前项目测试设施允许。
- 运行 `.\gradlew.bat :app:testDebugUnitTest`。
- 可行时运行 `.\gradlew.bat :app:assembleDebug`。

## 8. 暂不处理

- 不做多角色同场。
- 不做长期记忆总结。
- 不做角色卡导入导出。
- 不在聊天主界面展示当前视角或 Marker 状态。
- 不把 Marker 保存进历史消息或数据库。
- 不把剧情推进建议强制解释为用户台词。
